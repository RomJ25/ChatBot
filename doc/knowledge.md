# מערכת הידע של Sniro

מדריך לעריכת התוכן שהבוט יודע. קהל יעד: חברי צוות שעורכים
את המידע על הצוות והפרויקטים — לא מפתחים שעובדים על הקוד.

---

## מה המערכת עושה

Sniro הוא בוט **מקורקע (grounded)** — הוא עונה **אך ורק** על בסיס
המידע שמופיע בקבצי התוכן של הפרויקט. המודל לא מומצא עובדות, לא
מוסיף אנשים לצוות ולא ממציא פרויקטים. זה האפקט המבוקש:
**המקור היחיד לאמת הוא הקוד**.

אם תוסיף חבר צוות ל־`team.ts` — הבוט ידע עליו בבקשה הבאה.
אם תסיר פרויקט — הבוט יפסיק להכיר בו מיד.
אם תשאל על משהו שלא מופיע בתוכן — הבוט יענה "אין לי מידע על כך".

---

## זרימת הנתונים (Data Flow)

```
    src/content/team.ts         ┐
         (צוות + פרויקטים)       │
                                 ├──►  buildSystemPrompt()  ──►  system prompt
    src/content/knowledge.ts    │        (systemPrompt.ts)       (מחרוזת אחת
         (פריטי ידע חופשיים)     │                                 בעברית)
         + sources/external.ts   ┘                                     │
                                                                       ▼
                                                      ┌────────────────────────┐
                                                      │  נשלח ב־role: system   │
                                                      │  לפני כל שאלה של       │
                                                      │  המשתמש.               │
                                                      └────────────────────────┘
                                                                       │
                                                                       ▼
                                                              תשובה של המודל,
                                                              מבוססת רק על
                                                              המידע למעלה.
```

ה־prompt נבנה **מחדש בכל בקשה**. אין cache, אין dbstate. זה
אומר ששינוי בקובץ תוכן משפיע מיידית על התשובה הבאה (אחרי
טעינה מחודשת של המודול).

## מפת קבצים

```
src/content/
├── team.ts               # נתונים מובנים: שם הצוות, מפקד/ת, חברים, פרויקטים, טון
├── knowledge.ts          # פריטי ידע חופשיים: מושגים, שאלות, תהליכים, קישורים, הערות
├── systemPrompt.ts       # בונה את ה־prompt מהשניים. (לא צריך לגעת.)
└── sources/
    └── external.ts       # seam למקורות חיצוניים (Confluence, Notion) — ריק כרגע
```

**מה כן לערוך:** `team.ts`, `knowledge.ts`, ובעתיד `sources/`.
**מה לא לגעת:** `systemPrompt.ts` — הוא הבלייזר שמחבר הכל.

## לערוך את `team.ts`

זה המקום למידע **מובנה ובעל סכימה קבועה**: מי מפקד/ת, מי בצוות,
מה הפרויקטים. אם יש לזה שדה — זה כאן.

### להוסיף חבר/ת צוות

פתח את `src/content/team.ts` וחפש את המערך `members`. הוסף שורה:

```ts
members: [
  // ...
  {
    name: "שם מלא",
    responsibility: "תחום האחריות — משפט קצר על מה הוא/היא אחראי/ת",
  },
],
```

שדות:
- `name` — **חובה.** שם מלא.
- `responsibility` — מומלץ מאוד. מה האדם אחראי עליו.
- `role` — תפקיד/תואר (אופציונלי). לרוב מיועד למפקד/ת בלבד.

אם תגדיר גם `role` וגם `responsibility`, הם יוצגו יחד:
`**שם** (תפקיד) — תחום אחריות`.

### להסיר חבר/ת צוות

פשוט מחק את השורה. אין "קובץ היסטוריה" — הבוט יפסיק להזכיר
אותו/ה מיד.

### להחליף מפקד/ת

ערוך את השדה `commander` (יחיד, לא מערך). אותה סכימה כמו חבר/ת צוות:

```ts
commander: {
  name: "שם חדש",
  role: "קב״רית ומפקדת הצוות",
},
```

### להוסיף פרויקט

חפש את המערך `projects` והוסף:

```ts
projects: [
  // ...
  {
    name: "שם הפרויקט",
    description: "משפט אחד שמסביר מה הפרויקט עושה",
    status: "פעיל", // אופציונלי: פעיל / בפיתוח / הושלם / וכו׳
  },
],
```

רק `name` חובה. אם תשאיר `description` ריק, הפרויקט יופיע ברשימה
אבל בלי הסבר. **הבוט לא ימציא הסבר** — הוא פשוט יגיד את השם.

### לשנות את הטון של התשובות

השדה `tone` שולט באיך המודל עונה:

```ts
tone: {
  voice: "מקצועי, ענייני ונגיש. גאה בעשייה, לא מתחנף.",
  audience: "אנשים חיצוניים שרוצים להכיר את הצוות לראשונה.",
  language: "עברית",
},
```

שינוי ב־`voice` או `audience` יכול לשנות דרסטית את הרגשה של
התשובות. הבוט ינסה לעקוב.

### להחליף את הודעת הפתיחה

השדה `welcome` הוא הודעת הבוט הראשונה בצ'אט. אם תשאיר אותו ריק
(מחרוזת ריקה), נגזור ברירת מחדל מתוך `name`:

```ts
welcome: "", // → "שלום! אני העוזר החכם של צוות שניר. ..."
```

או תכתוב משלך:

```ts
welcome: "היי! אני הבוט של הצוות. מה בא לך לדעת?",
```

ההודעה תומכת ב־Markdown מלא — אפשר **הדגשות**, רשימות, לינקים.

## לערוך את `knowledge.ts`

זה המקום לידע **חופשי, בלי סכימה קבועה** — מושגים שאין להם
עמודה בטבלה של `team.ts`. לדוגמה: הגדרה של מילה פנימית, הסבר
איך תהליך עובד, שאלה נפוצה, לינק למסמך חיצוני.

### המבנה

כל פריט ידע נראה כך:

```ts
{
  id: "glossary.something-unique",
  kind: "glossary",
  title: "כותרת הפריט",
  body: "גוף הטקסט, תומך ב־Markdown.",
  tags: ["מבנה"], // אופציונלי
},
```

שדות חובה: `id`, `kind`, `title`, `body`.

**ה־`id`** הוא מזהה יציב — אם תרצה שמישהו יתייחס לפריט הזה,
זה המזהה שלא משתנה. המוסכמה: `<kind>.<שם-קצר-באנגלית>`, לדוגמה
`glossary.molecule`, `faq.contact`.

### חמשת סוגי הפריטים (kinds)

| `kind` | למה זה משמש | איפה מוצג ב־prompt |
|---|---|---|
| `glossary` | הגדרה של מושג פנימי | תחת "## מושגים" |
| `process` | הסבר איך תהליך עובד | תחת "## תהליכים" |
| `faq` | שאלה נפוצה + תשובה | תחת "## שאלות נפוצות" |
| `link` | הפנייה למשאב חיצוני | תחת "## קישורים" |
| `note` | הערה חופשית | תחת "## הערות" |

כולם משותפים לאותו prompt. הסדר קבוע — קודם מושגים, אחר כך
תהליכים וכו׳. אם אין פריטים מסוג מסוים, הכותרת פשוט לא תופיע.

### דוגמאות מוכנות להעתקה

**מושג (glossary):**

```ts
{
  id: "glossary.molecule",
  kind: "glossary",
  title: "מולקולה",
  body: "יחידה לוגית בתוך המכלול. כל מולקולה אחראית על תחום ספציפי, וכל חבר צוות אחראי על מולקולה אחת או יותר.",
  tags: ["מבנה"],
},
```

**תהליך (process):**

```ts
{
  id: "process.new-project",
  kind: "process",
  title: "כיצד נבחרים פרויקטים חדשים",
  body: "פרויקטים חדשים מתחילים כיוזמה של חבר צוות, עוברים תיאום מול המפקדת, ונכנסים לתעדוף הצוותי.",
  tags: ["תהליך", "פרויקטים"],
},
```

**שאלה נפוצה (faq):**

```ts
{
  id: "faq.contact",
  kind: "faq",
  title: "איך יוצרים קשר עם הצוות?",
  body: "ניתן לפנות ישירות לכל אחד מחברי הצוות או למפקדת הצוות (ליאם כהן).",
  tags: ["קשר"],
},
```

**קישור (link):**

```ts
{
  id: "link.wiki-home",
  kind: "link",
  title: "ויקי הצוות",
  body: "**כתובת:** https://example.internal/wiki/sniro",
  tags: ["קישור"],
},
```

**הערה חופשית (note):**

```ts
{
  id: "note.naming-convention",
  kind: "note",
  title: "מוסכמת שמות לקבצי קלט",
  body: "שם הקובץ מתחיל בשם המולקולה, אחריו `_YYYY-MM-DD_`, ואז שם תמציתי.",
},
```

### גוף רב־שורות

אם ה־`body` ארוך מ־120 תווים או מכיל ירידות שורה, הוא יוצג
מתחת לכותרת בהזחה (לא בשורה אחת). Markdown מלא נתמך:

```ts
{
  id: "process.onboarding",
  kind: "process",
  title: "קליטת חבר צוות חדש",
  body: `שלבים:
1. פגישת היכרות עם המפקדת.
2. קריאת **מסמך החזון** של הצוות.
3. התחברות לרפוזיטורי המרכזי וקריאת ה־README.
4. שיחת עומק עם בעל/ת המולקולה הראשונה שיטפל/תטפל בה.`,
},
```

### להסיר פריט

מחק את אובייקט הפריט מהמערך `HAND_AUTHORED` (או הפוך אותו
להערה עם `//`). הפריט ייעלם מה־prompt מיידית.

### תגיות (`tags`)

לא משפיעות על הבוט כרגע — הן נשמרות לעתיד (סינון בממשק,
חיפוש). ככה ש**לא חייב** להוסיף תגיות, אבל אם כבר אתה שם
פריט — שווה לסווג.

## מקורות חיצוניים (Future)

הקובץ `src/content/sources/external.ts` הוא **seam** — נקודת
חיבור עתידית למערכות כמו Confluence, Notion או ויקי פנימי.
כרגע הוא ריק.

הרעיון: סקריפט יקרא תוכן ממקור חיצוני, ייצור קובץ כמו
`sources/confluence.generated.ts` עם מערך `KnowledgeItem[]`, ו־
`external.ts` יאחד את כולם. `knowledge.ts` כבר מצרף את
`EXTERNAL` למערך `KNOWLEDGE` — שום דבר אחר לא צריך להשתנות.

פירוט מלא של הדפוס בקובץ עצמו (`sources/external.ts`).
בשלב הזה אין צורך לגעת בזה.

## תזרים עבודה (Dev Workflow)

### לשנות תוכן ולראות מיידית

```bash
npm run dev         # http://localhost:5173
# עורך את team.ts או knowledge.ts
# Vite מזהה את השינוי ומרענן את הדף אוטומטית
# השאלה הבאה שתשאל תשתמש בתוכן המעודכן
```

Vite HMR (Hot Module Replacement) עובד מצוין כאן: עריכת קובץ
תוכן לא דורשת רענון ידני. אם בכל זאת משהו נראה תקוע, אחד
הפתרונות הבאים יעזור:

1. **שאל שאלה חדשה** — ה־prompt נבנה מחדש בכל בקשה, אז השאלה
   הבאה תשתמש בתוכן המעודכן גם אם הדף לא התרענן ויזואלית.
2. **רענן את הדף** — תמיד עובד.
3. **הפעל מחדש את dev server** — רק אם שינית גם `.env.local` או
   `vite.config.ts`.

### לבנות ל־production

```bash
npm run build       # בדיקת טיפוסים + bundle ל־dist/
npm run preview     # מריץ את ה־build מקומית לבדיקה
```

התוכן הוא חלק מה־bundle — עריכת `team.ts` בסביבת production
דורשת בנייה מחדש.

## Override ידני של ה־prompt

אם מסיבה כלשהי אתה רוצה לעקוף את הבנייה האוטומטית ולהגדיר
prompt לחלוטין משלך, הגדר ב־`.env.local`:

```
VITE_LLM_SYSTEM_PROMPT="הטקסט המלא של ה־prompt כאן"
```

**כשמוגדר**, הוא דורס לגמרי את מה ש־`buildSystemPrompt` מייצר.
כל התוכן ב־`team.ts`/`knowledge.ts` **מתעלמים ממנו**. זה כלי
לשעת חירום או לניסוי — בשימוש רגיל, העדף לערוך את קבצי התוכן.

## Debugging — מה לבדוק אם התשובות לא הגיוניות

### הבוט לא מזכיר חבר/ת צוות שהוספתי

1. ודא ששמרת את הקובץ (`team.ts`).
2. בדוק שאין שגיאת syntax — TypeScript יציג שגיאה בטרמינל של
   `npm run dev`.
3. רענן את הדף.
4. שאל ישירות: "מי אחראי על X?" — אם הבוט לא יודע, פתח את
   DevTools → Network, מצא את בקשת `/api/llm/chat/completions`
   האחרונה, והסתכל ב־`messages[0].content` (ה־system prompt).
   אם השם לא שם — הבעיה בתוכן. אם השם כן שם — ה־LLM החליט
   להתעלם.

### הבוט "ממציא" פרטים שלא קיימים

זה קורה לפעמים — דגמים קטנים נוטים לפרש/להרחיב. שתי אסטרטגיות:

1. **חדד את ה־`body`** בפריט הידע — תן יותר הקשר ופחות מקום
   לפרשנות.
2. **החלף דגם** — `.env.local` → `VITE_LLM_MODEL=<דגם חזק יותר>`.

הבוט כבר מקבל הוראה מפורשת "אל תמציא", אבל זה רמז — לא
אכיפה. דגם חזק יותר מציית יותר טוב.

### הבוט עונה באנגלית למרות שהתוכן בעברית

בדוק ש־`team.ts` → `tone.language = "עברית"`. ה־prompt אומר
במפורש "ענה תמיד בעברית". אם עדיין חוזר באנגלית, זה בדרך כלל
בעיה של הדגם — החלף דגם.

### שיניתי תוכן ולא רואה את זה בדפדפן

- ודא שה־dev server רץ (`npm run dev`).
- ודא ששמרת את הקובץ.
- רענן את הדף.
- אם עדיין לא — הפעל מחדש את ה־dev server.

## TL;DR

- **`team.ts`** — מידע מובנה (מי, מה, פרויקטים). המקור הראשי.
- **`knowledge.ts`** — ידע חופשי (מושגים, תהליכים, שאלות, קישורים, הערות).
- **שינוי = שמירה + רענון** — זהו. אין database, אין migrations.
- **הבוט יודע רק מה שכתוב שם.** אין מצב שהוא "למד מעבר" — אם
  חסר, תוסיף.
